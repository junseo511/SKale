# 01. SKale PRD 및 기능명세서 개선본

> **서비스명:** SKale  
> **의미:** SK + Scale. 소비와 자산의 규모를 측정하고, 자산 배분의 비중을 조정하며, 장기적으로 자산을 키운다는 의미.  
> **슬로건:** AI로 소비를 읽고, 자산을 키우다.

---

## 1. 제품 정의

SKale은 사용자가 입력하거나 캡처한 소비 내역과 자산 현황을 AI가 구조화하고, 소비 카테고리 분류·순자산 계산·이전 대비 변화·자산 배분·투자 전략 기반 종목 분석까지 연결하는 개인 자산관리 AI Agent이다.

단순 가계부가 아니라 다음 질문에 답하는 것을 목표로 한다.

- 이번 달 돈이 어디로 흘러갔는가?
- 고정비, 생활비, 여행, 투자 비중은 적절한가?
- 지난 기록 대비 순자산은 좋아졌는가?
- 현재 투자 여력은 있는가?
- 내 투자 성향과 전략에 맞는 자산 배분은 무엇인가?
- 관심 종목은 내 전략 기준에서 검토할 만한가?

## 2. 초안 점검 결과

### 2.1 잘 작성된 부분

| 항목 | 평가 |
|---|---|
| 서비스 콘셉트 | 소비·자산·투자까지 이어지는 흐름이 명확함 |
| MVP 범위 | 직접 입력, 캡처, 차트, 포트폴리오 추천으로 시연 가치가 있음 |
| 화면 구성 | Dashboard / 소비 분석 / 자산 분석 / 포트폴리오로 단순하고 이해하기 쉬움 |
| 제출 적합성 | “개인의 일상과 성장을 돕는 AI Agent” 주제와 잘 맞음 |
| 시연 안정성 | 예시 데이터 버튼과 mock fallback 방향이 적절함 |

### 2.2 보강이 필요한 부분

| 항목 | 문제 | 개선 방향 |
|---|---|---|
| 프롬프트 | JSON만 요구하고 검증 규칙이 약함 | JSON Schema, confidence, needReview, missingData 추가 |
| 캡처 분석 | OCR 오류와 민감정보 위험 대응이 부족함 | 베타 표시, 수동 수정 UI, 민감정보 가림 안내 추가 |
| 자산 분석 | 이체/입금/투자를 소비와 혼동할 수 있음 | transactionType, cashFlowType 분리 |
| 포트폴리오 추천 | 투자 조언으로 오해될 수 있음 | “참고용 분석”, “검토 후보군”, “매수/매도 지시 아님” 고정 |
| 종목 분석 | 최신 재무 데이터가 없으면 환각 위험 | 사용자가 제공한 데이터만 분석하거나 데이터 부족 표시 |
| 사용자 도움 | 결과 설명은 있으나 다음 행동이 약함 | actionItems, warningSignals, nextCheckDate 추가 |

## 3. MVP 범위 재정의

### 3.1 필수 구현 기능

| 우선순위 | 기능 | 설명 |
|---:|---|---|
| 1 | 소비 내역 직접 입력 분석 | 텍스트 소비 내역을 구조화하고 카테고리 분류 |
| 1 | 소비 결과 시각화 | 카테고리별 지출 합계와 비중 표시 |

| 1 | 대시보드 | 소비, 자산, AI 코멘트 요약 |

## 4. 핵심 기능명세

## 4.1 Dashboard

### 목적

사용자가 소비, 자산, 투자 상태를 첫 화면에서 한눈에 확인한다.

### 표시 항목

- 이번 달 총지출
- 고정비 비중
- 변동비 비중
- 순자산
- 이전 대비 순자산 변화
- 카테고리별 지출 차트
- 자산 구성 차트
- AI 한 줄 코멘트
- 다음 추천 행동 3개

### 추가 개선 포인트

초안에는 요약 카드와 차트는 있었지만, 실제 사용자에게 도움이 되려면 **다음 행동**이 있어야 한다.

예시:

```text
다음 행동
1. 이번 달 카페/외식 지출이 평균보다 높으니 남은 기간 식비 한도를 12만 원으로 잡아보세요.
2. 순자산은 증가했지만 현금성 자산 비중이 낮습니다. 비상금 목표를 먼저 채워보세요.
3. 투자 여력은 있어 보이지만 카드 미결제가 남아 있으므로 월말 결제 후 투자 금액을 확정하세요.
```

## 4.2 소비 분석

### 목적

사용자의 결제 내역을 소비/저축/투자/이체 성격으로 구분하고, 소비 내역은 카테고리별로 분류한다.

### 입력 방식

- 직접 입력
- 이미지 업로드
- 예시 데이터 불러오기

### 출력 항목

- 날짜
- 사용처
- 금액
- 카테고리
- 거래 성격
- 고정비 여부
- 분류 신뢰도
- 확인 필요 여부
- 분류 이유

### 카테고리

| 카테고리 | 예시 |
|---|---|
| 고정비 | 월세, 관리비, 통신비, 구독료 |
| 생활비 | 마트, 편의점, 생필품 |
| 식비/카페 | 식당, 배달, 카페 |
| 교통 | 지하철, 버스, 택시, 주유 |
| 쇼핑 | 의류, 전자기기, 잡화 |
| 여행 | 항공권, 숙박, 여행지 결제 |
| 의료/건강 | 병원, 약국, 운동 |
| 데이트 | 선물, 외식, 문화생활 |
| 투자 | 증권사 입금, ETF, 주식 |
| 저축 | 예금, 적금, 청약 |
| 이체/정산 | 친구 송금, 계좌 이동 |
| 기타 | 불명확한 항목 |

### 중요한 개선점

투자, 저축, 이체는 일반 소비와 다르다. 따라서 `expense`만 쓰면 안 되고 다음처럼 분리한다.

```typescript
export type TransactionNature =
  | "expense"
  | "fixedExpense"
  | "saving"
  | "investment"
  | "transfer"
  | "income"
  | "unknown";
```

## 4.3 자산 분석

### 목적

은행/증권/카드 앱에 흩어진 자산 상태를 구조화하고 순자산을 계산한다.

### 출력 항목

- 총자산
- 총부채
- 순자산
- 현금성 자산
- 저축성 자산
- 투자 자산
- 목적 자금
- 미결제/부채
- 이전 대비 변화
- 자산 건강 코멘트
- 다음 행동

### 자산 건강 판단 기준

| 항목 | 판단 기준 |
|---|---|
| 비상금 | 월 생활비 3개월 미만이면 경고 |
| 부채 | 순자산 대비 부채 비중이 높으면 경고 |
| 현금 비중 | 투자 자산 대비 현금이 지나치게 낮으면 경고 |
| 투자 여력 | 카드 미결제와 고정비를 제외한 후 계산 |
| 목적 자금 | 여행/이사/결혼 등 단기 목표 자금은 투자금과 분리 |

---

## 4.4 포트폴리오 추천

### 목적

사용자의 투자 성향, 기간, 월 투자 가능 금액, 자산 상태, 투자 전략을 기반으로 자산 배분 방향을 제안한다.

### 원칙

- 매수/매도 지시를 하지 않는다.
- 구체 종목은 “추천”이 아니라 “검토 후보”로 표현한다.
- 현재 재무 데이터가 없으면 종목 분석은 보류한다.
- 비상금과 카드 미결제를 먼저 확인한다.
- 사용자의 투자 전략을 반영하되, 위험 신호를 반드시 함께 표시한다.

### 출력 항목

- 추천 자산 배분
- 추천 이유
- 현재 자산 상태에서의 우선순위
- 투자 가능 금액 산정 근거
- 리스크 코멘트
- 다음 확인 지표
- 투자 고지 문구

## 4.5 주식 종목 분석

### 목적

사용자가 입력한 종목을 간소화된 stock_strategy 기준으로 분석해, 장기 투자 검토 후보인지 판단한다.

### 반드시 필요한 데이터

- 종목명
- 산업/사업 설명
- 최근 3년 매출 추이
- 매출총이익률 또는 영업이익률 추이
- 영업현금흐름
- 자유현금흐름
- 부채 관련 지표
- 주요 리스크
- 현재 밸류에이션 지표

### 데이터가 부족할 때 처리

AI는 부족한 데이터를 상상해서 채우지 않는다.

```json
{
  "verdict": "데이터 부족",
  "missingData": [
    "최근 3년 매출",
    "영업현금흐름",
    "부채비율",
    "현재 밸류에이션"
  ],
  "message": "현재 제공된 정보만으로는 전략 기준에 따른 종목 분석을 완료할 수 없습니다."
}
```

## 5. 비기능 요구사항

### 5.1 AI 안정성

- 모든 AI 응답은 JSON Schema를 기준으로 파싱한다.
- `confidence < 0.75`인 항목은 확인 필요로 표시한다.
- AI가 모르는 정보는 `missingData`에 넣는다.
- API 실패 시 mock fallback을 제공한다.
- 투자 관련 응답에는 고지 문구를 포함한다.

### 5.2 개인정보 보호

- 실제 계좌번호, 카드번호, 주민등록번호 입력을 권장하지 않는다.
- 캡처 업로드 영역에 민감정보 가림 안내를 표시한다.
- MVP에서는 localStorage만 사용하고 서버 저장은 하지 않는다.

### 5.3 시연 안정성

- 모든 화면에 예시 데이터 버튼을 둔다.
- 네트워크 오류가 나도 예시 결과로 흐름을 설명할 수 있어야 한다.
- 모바일 화면에서도 핵심 카드가 깨지지 않아야 한다.

## 6. 최종 완료 기준

- 대시보드가 정상 표시된다.
- 소비 내역 직접 입력 분석이 동작한다.
- 소비 카테고리 차트가 표시된다.
- 자산 입력 분석이 동작한다.
- 이전 자산 대비 변화가 표시된다.
- 포트폴리오 추천이 표시된다.
- 종목 분석은 데이터 부족 시 정직하게 부족 항목을 표시한다.
- 예시 데이터만으로 1분 시연이 가능하다.
- 외부 URL 접속이 가능하다.
